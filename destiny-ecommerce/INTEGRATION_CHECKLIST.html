1. Domain & Hosting
Where your app lives on the internet
Required ▼
  • Register a domain name ~$12/yr
    Recommended: Namecheap or GoDaddy. Suggested: destiny-ecommerce.cm (Cameroon TLD) or .com
  • Choose API hosting $5–20/mo
    Options: Railway (easiest), Render.com, DigitalOcean App Platform, or VPS. Railway free tier: 500hrs/month
  • Choose Next.js hosting
    Free tier Vercel (recommended — built for Next.js) or Netlify. Set up at vercel.com
  • Point DNS to hosting
    Add A/CNAME records in your domain registrar pointing to your deployed app URLs
  • Configure SSL certificates
    Auto Vercel and Railway auto-provision Let's Encrypt SSL. Required for payment flows.

2. PostgreSQL Database
Primary data store for all platform data
Required ▼
  • Create PostgreSQL database Free tier available
    Options: Supabase (free 500MB), Neon (free 3GB), Railway PostgreSQL, or PlanetScale. Get connection string.
  • Set DATABASE_URL environment variable
    postgresql://user:password@host:5432/destiny_db?schema=public&sslmode=require
  • Run Prisma migrations
    From apps/api/ run: npx prisma migrate deploy (production) or npx prisma migrate dev (dev)
  • Generate Prisma client
    npx prisma generate — must run after every schema change
  • Seed initial data (optional)
    npx ts-node prisma/seed.ts — creates admin user, sample categories, and brands
  • Set up Redis (optional, for caching)
    Free tier Upstash Redis. Set REDIS_URL. Falls back gracefully if not set.
🔐
3. Authentication Setup
JWT secrets and OAuth providers
Required ▼
  • Generate JWT secrets Critical
    Run: openssl rand -base64 64 twice — once for JWT_SECRET, once for JWT_REFRESH_SECRET. Never reuse.
  • Create first SUPER_ADMIN account
    Register via POST /api/v1/auth/register then update role in DB: UPDATE users SET role = 'SUPER_ADMIN' WHERE email = 'your@email.com';
  • Google OAuth (optional)
    Create project at console.cloud.google.com → Credentials → OAuth 2.0 Client ID. Set redirect URI to https://yourdomain.com/api/v1/auth/google/callback. Copy GOOGLE_CLIENT_ID and GOOGLE_CLIENT_SECRET.
  • Facebook OAuth (optional)
    Create app at developers.facebook.com → Facebook Login. Set redirect URI. Copy FACEBOOK_APP_ID and FACEBOOK_APP_SECRET.

5. Email Notifications
Order confirmations, password resets, shipping updates
Recommended ▼
Graceful degradation: If SMTP is not configured, all emails are logged to console instead of crashing the server.
  • Create SendGrid account Free 100 emails/day
    Register at sendgrid.com → Settings → API Keys → Create API Key (Full Access). Set SMTP_HOST=smtp.sendgrid.net, SMTP_PORT=587, SMTP_USER=apikey, SMTP_PASS=your_api_key
  • Alternative: Gmail SMTP
    Enable 2FA → App Passwords → Generate. Set SMTP_HOST=smtp.gmail.com, SMTP_PORT=587, SMTP_USER=your@gmail.com, SMTP_PASS=app_password
  • Set SMTP_FROM_EMAIL and SMTP_FROM_NAME
    Example: SMTP_FROM_EMAIL=hello@destiny-ecommerce.com and SMTP_FROM_NAME=Destiny E-Commerce
  • Verify sender domain (SendGrid)
    Add DNS TXT/CNAME records from SendGrid to authenticate your domain. Prevents spam filtering.

6. SMS Notifications (Africa's Talking)
Order alerts and OTP via SMS to Cameroon numbers
Optional ▼
  • Create Africa's Talking account
    Register at africastalking.com. Free sandbox for testing. Production requires funding account.
  • Get API key and username
    Dashboard → Settings → API Key. Set AT_API_KEY and AT_USERNAME (sandbox uses "sandbox")
  • Register Sender ID (optional)
    Apply for branded sender like "DESTINY" — takes 2–4 weeks. Set AT_SENDER_ID=Destiny. Without it, uses a random short code.
  • Top up account balance
    ~0.8 XAF per SMS to Cameroon numbers. $10 credit = ~6,500 SMS messages.

11. Security Hardening
Production security checklist
Required ▼
  • Set NODE_ENV=production
    Disables verbose Prisma logging, enables security middleware, hides stack traces in errors
  • Use strong, unique secrets for all keys
    Critical JWT_SECRET min 64 chars. Never commit .env to git.
  • Configure CORS for your domain
    Set CORS_ORIGIN=https://yourdomain.com to restrict cross-origin requests
  • Rate limiting is pre-configured
    @nestjs/throttler limits to 10 requests/second per IP. Adjust TTL/LIMIT in throttler module if needed.
  • Set up database backups
    Supabase/Neon auto-backup daily. For self-hosted Postgres: set up pg_dump cron job or use Barman.
  • Configure error monitoring (optional) Free tier
    Sentry.io: register → create project → copy DSN → set SENTRY_DSN

13. Deployment Steps
Railway (API) + Vercel (Frontend)
Required ▼
  • Deploy API to Railway
    railway.app → New Project → Deploy from GitHub → select repo → set root dir to destiny-ecommerce/apps/api → add all env vars → deploy
  • Run migrations on Railway
    Railway shell or build command: npx prisma migrate deploy && node dist/main
  • Deploy frontend to Vercel
    vercel.com → New Project → Import GitHub → set root dir to destiny-ecommerce/apps/web → add env vars → deploy
  • Set NEXT_PUBLIC_API_URL on Vercel
    Vercel project → Settings → Environment Variables → add NEXT_PUBLIC_API_URL=https://your-railway-api-url/api/v1
  • Verify health endpoint
    Visit https://api.yourdomain.com/api/v1/health — should return {"status":"ok"}
  • Test authentication flow
    Register → login → check JWT in localStorage → verify admin redirect works
  • Test end-to-end order flow
    Browse → Add to cart → Checkout → Select MTN/Orange → Place order → Submit payment proof → Admin approves
  • Test email notifications
    Place order and verify confirmation email arrives. Check spam folder first time.
